# Gate E5 — the geometry kernel against hulls somebody else drew

**What this gate is for.** Every other geometry test in this repository asks
the kernel about hulls the kernel invented. `vector(named(x)) == x` on a
sampled genome, the slider fixture, a Pareto front — all of them are
self-consistency, and a wrong kernel is self-consistent too. E5 is the one
test that hands the kernel a hull drawn by someone else, decades ago, in a
towing tank, and asks it to come back.

- Provenance and the acquisition record: **`data/e5_sources.md`**
- The measurements: **`data/e5_real_hulls.json` / `.csv`**
- The evidence: **`tests/e5_real_hulls/<id>/source_offsets.csv`**
- The gate: **`tests/test_e5_real_hulls.py`** (`Gate 0E5`)

---

## The evidence chain

The chain the corpus is built on, and each link is a separate artifact so a
break in one is visible:

```
published source
  -> published geometry (IGES surface, or a printed offsets table, or a closed form)
    -> offsets extracted INDEPENDENTLY                tests/e5_real_hulls/<id>/source_offsets.csv
      -> particulars computed INDEPENDENTLY           benchmarks/e5_hydro.py
        -> NavalAI genome (six pinned, ten fitted)    scripts/e5_roundtrip.py
          -> generated hull                           navalai/geometry.py
            -> measured back, SAME independent code   benchmarks/e5_hydro.py
              -> scalar residual AND shape residual
```

**`benchmarks/e5_hydro.py` imports no part of the kernel it measures**, and a
test enforces that by reading its source. The shortcut — measure the
published hull with `hydrostatics.solve`, which is right there and already
works — would reduce the whole exercise to `solve(x) == solve(x)` while still
printing a table of impressive agreements.

### The instrument was verified before anything was measured with it

Against two hulls whose answers are known in closed form, not against
consensus:

| case | quantity | exact | measured |
|---|---|---|---|
| Wigley parabolic | volume `4LBT/9` | — | −0.017% |
| Wigley parabolic | `Cp = Cm = 2/3` | — | −0.016% |
| Wigley parabolic | LCB (symmetric) | 0 | **0.000000%** |
| box, immersed transom | volume `LBT` | 30.0 | **30.0000** |
| box, immersed transom | `Cp`, `Cb` | 1.0 | **1.0000** |

The Wigley residuals fall as `1/n²` on refinement — the Cm error runs
−0.0977, −0.0244, −0.0061, −0.0015, −0.0004% as the waterline count doubles —
which is second-order trapezoid convergence and not a bug.

## Conventions, which is where this kind of work actually goes wrong

Every value in the ledger carries the source's own convention **and** the
transformation applied. "No conversion needed" is written down, because
afterwards it is indistinguishable from never having checked.

**LCB is normalised to one convention: percent of LWL, positive forward of
amidships.** The cost of not doing this is not hypothetical. DSYHS publishes
`lcb0` in metres from half the waterline length; converting it gives
−2.29% for Sysser 1, while the geometry gives −2.14%, a 6.7% relative
disagreement that looks like a real error. It is not:

| | absolute LCB, from the aft end of the table |
|---|---|
| measured from the published IGES | 763.31 mm |
| implied by the published table | 763.36 mm |

**0.05 mm apart on a 1.6 m hull.** The two sources put the centre of buoyancy
in the same place to three thousandths of a percent; the percentages differ
only because each is divided by its own LWL, and those LWLs differ by 0.5%.
A percentage is not a position.

**Draft.** DSYHS `tc0` is the *maximum canoe-body* draft; the genome's `T` is
the draft at the midship keel. On a hull with rocker those are not the same
station. The difference is carried in the ledger, not absorbed.

**Depth.** See below — it is the parameter this corpus nearly did not have.

## Findings

### 1. The DSYHS geometry release and the DSYHS hydrostatics table disagree

Both are published by TU Delft, both were MD5-verified against the
publisher's own checksums, and they do not describe quite the same hulls.
Measured by extracting offsets from the IGES surfaces and computing
hydrostatics independently:

| quantity | agreement with the published table |
|---|---|
| displaced volume | within ~1.5%, mostly better than 0.3% |
| waterplane area | within ~1.3% |
| maximum section area | within ~0.3% |
| **absolute LCB** | **0.003%** |
| prismatic coefficient | within ~0.6% |
| **waterline length** | **systematically +0.5%** (+0.29 … +0.67%) |
| **waterline beam** | **0 to +1.1%**, and bimodal across the series |

The waterline length disagreement is not a scan artefact: the crossing where
the keel line meets the design waterline was located by bisection to
0.001 mm, and it puts the aft end at x = −6.32 mm and the forward end at
x = 1601.67 mm on a hull whose published LWL is 1600.00 mm. Nor is it a
mis-placed waterline — dropping the waterline by 3 mm to close the beam gap
costs 4.5% of the displaced volume, which then disagrees far worse.

The likely explanation is in the IGES header: the surfaces are *"Rhino
modellen na inmeten 2012"* — Rhino models built from a **2012 re-measurement
of the physical models**, while the hydrostatics table descends from the
original 1970s reports. A GRP model that measures half a percent longer than
its drawing is unremarkable; two published artifacts that disagree without
saying so is worth recording. `Cb`, `Cm` and `Cw` inherit the beam
discrepancy exactly, because all three divide by it.

**For E5 the source of truth is the GEOMETRY**, since geometry is what the
kernel is being asked to reproduce. The table's values are recorded beside it
as the independent cross-check that validated the extraction in the first
place.

### 2. Depth is the parameter that systematic series do not publish

A towing-tank series publishes the **submerged body**. Its hydrostatics are
canoe-body hydrostatics; there is no sheerline, and therefore no `D`. This
is not an oversight in one dataset — it is what the whole genre publishes,
and it is why the brief's warning not to invent `D` from a photograph is the
right warning.

`D` survives here for exactly one reason: the DSYHS models were **designed to
a constant freeboard**, so the published IGES surface is truncated at a flat
constant-z line — 318.10 mm on Sysser 1, identical at all 41 stations — which
is a designed deck height rather than an arbitrary trim. Two independent
routes to it agree:

| route | D, full scale, Sysser 1 | freeboard |
|---|---|---|
| Report 452-P p. 14: *"the constant freeboard (1.15 m) plus the draught of the canoe body"* | 1.944 m | 1.150 m |
| measured from the published IGES at amidships | 1.988 m | 1.194 m |

**+2.3%**, from a printed 1977 design rule and a 2012 laser re-measurement.
Both are recorded; neither is discarded.

Where a source has no sheerline at all — the Wigley form has no deck —
`D` is recorded as **UNAVAILABLE**, the hull is marked *partial evidence*,
and it does not count toward the gate's complete-hull total.

### 3. The genome is sixteen genes, and E5 must not pretend it is six

`LWL, BWL, T, D, Cp, LCB` do not determine a hull, and NavalAI has never
claimed they do: `grammar.PARAMS` has sixteen entries, and the other ten
(`x_mb`, `r_transom`, `beta_mid`, `beta_bow`, `beta_len`, `roundness`,
`rocker`, `forefoot`, `flare`, `sheer_rise`) are what fix the *shape*.

This makes the scalar round-trip the weaker of the two tests, and it is
reported as such. `Cp` and `lcb` are genes the kernel **solves** to, so a
pass largely confirms the solver converged. The corpus bears that out: the
largest scalar deviation on any hull is LCB by ~0.01 percentage points and
depth by ~3 mm.

**The geometric residual is the headline.** With the six pinned at the
source's values, the ten shape genes are fitted to the source's own offsets,
and what remains is the distance between a real published hull and the
nearest hull this grammar can express. That residual is not an error to be
tuned away — it is the result.

### 4. Where the error lives

Attributing the residual is the whole point of question 16, and the corpus
separates the three candidates cleanly:

- **Not the source.** The extraction reproduces published volume, waterplane
  area, section area and absolute LCB to a few tenths of a percent, and
  reproduces two closed forms to machine precision.
- **Not the parameterisation of the six.** They come back within
  10⁻² of what was commanded.
- **The grammar's shape vocabulary.** The residual tracks how far a hull is
  from the small-craft form the grammar was written for. A parabolic
  mathematical hull and a yacht canoe body sit low; a full merchant form sits
  far higher, and the reason is structural rather than numerical: **the
  grammar has no parallel-middle-body gene and no flat-of-bottom gene.**
  `x_mb` places a single maximum-area station, so a hull with a long constant
  midsection cannot be expressed at all, and `beta_mid` rotates a deadrise
  line where Series 60 has a flat floor with a bilge radius.

**That missing information is itself the E5 finding.** Nothing here was
adjusted to hide it.

### 5. What this corpus does NOT validate

Every hull in it is round-bilge or mathematical. **There is no hard-chine
hull.** NavalAI exists to design plywood stitch-and-glue boats, which are
hard-chine by construction, so E5 validates the geometry kernel over a
regime that is *not* the product's own. `roundness = 0` — the chine end of
the grammar's own range — is exercised by no source in this corpus.

The candidate that would close it is recorded in `data/e5_sources.md` and
`docs/audit/GATE2-PHYSICS-STACK.md`: the Compton (1986) USNA semi-planing
transom-stern series. Until it is acquired, this gate being green does not
mean chine geometry is validated, and no document should say it does.

## What was NOT done to make this pass

Stated explicitly, because each of these would have worked and none was used:

- no tolerance was widened to admit a hull;
- no hull was dropped for fitting badly — the worst residuals are named;
- the six are never allowed to drift during the fit (`_assert_six_held`
  raises, and a test re-checks the stored genomes);
- no source value was replaced with a generated one;
- no LCB convention was changed silently;
- no screenshot was used as geometry.

### Three defects were found in the measuring code itself

Each was caught by a case that *could* expose it, which is the argument for
a corpus with more than one kind of hull in it:

1. **An immersed transom lost its own sectional area.** The area was pinned
   to zero at both waterline ends unconditionally. A canoe body ends in a
   point, so 51 DSYHS hulls agreed with that perfectly; on a hull whose
   aftmost station is immersed, the pinned zero landed at the transom's own
   x and the duplicate-x guard kept the *zero*. Found by round-tripping a
   generated hull, which has a transom. Regression: a box, which has an exact
   answer and no taper at all.
2. **The offsets CSV wrote waterline heights to 5 decimals and the design
   waterline to 6.** On any hull whose draft is not a round number the
   tabulated DWL row therefore no longer *equalled* the DWL: one station
   dropped out of the wetted set and Series 60 read Cp 0.6056 against 0.6122.
   A 1.1% error, silent, in the artifact of record.
3. **An unreadable design waterline fell back to the top of the table.**
   That measured a Series 60 hull at 1.5× its draft, reported `T` = 1.600 m
   for a hull drawing 1.067 m and `Cp` 0.6608 for a published 0.614, then
   handed the kernel a hull with zero freeboard, which died dividing by it.
   Every one of those numbers looked like a result. An unreadable datum is
   now a refusal — the same rule as `${VAR:-0}` in the CFD receipts.

## Reproducing it

```bash
python scripts/fetch_e5_geometry.py      # 16 MB, publisher MD5 verified
python scripts/build_e5_dsyhs.py         # IGES -> offsets, ~1 min/hull
python scripts/build_e5_other.py         # Series 60 + Wigley fixtures
python scripts/build_e5_corpus.py        # round-trips -> the ledger
python scripts/e5_report.py --write      # regenerate the block above
python -m pytest tests/test_e5_real_hulls.py -q
```

The gate itself needs none of that: it reads the committed offset tables, so
it runs without OpenCASCADE and without the download.
